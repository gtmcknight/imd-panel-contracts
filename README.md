# IMD panels onchain: contract spec

Write two Solidity contracts that put the imd.fun wall's panels on Ethereum mainnet, then deploy them in one launch.
The tests in `test/` are the acceptance bar: every one must pass, unchanged.

What is given, and must not be changed:

- `art/imd-panel.js.gz`: the gzipped drawing code, 87,700 bytes, keccak256
  `0xd2c66890e2d2dc456f117c14ff12435ffc6fa56b73ab7955f0d838d8ae76cb76`.
  Its source is in `art/source`; `art/build.sh` rebuilds it byte for byte (esbuild 0.24.0, Node v24.10.0's zlib) and
  says whether it matches.
- `src/code/PanelCode0.sol` to `PanelCode3.sol`: that code split into four data contracts, generated by
  `tools/gen-code.py`. Each one's deployed bytecode is a STOP byte (`0x00`) followed by its part of the code.
- `test/`: the tests.
- `foundry.toml`: the build and test settings.

What you write: `src/PanelDesigns.sol` and `src/PanelRenderer.sol`.

## Toolchain

Solidity 0.8.28, EVM `cancun`, optimizer on (10,000 runs), Foundry 1.8.3 or later. See `foundry.toml`.
`forge build && forge test` must pass with no network access, so solc 0.8.28 must already be installed where Foundry finds it.

## PanelDesigns

One `bytes32` per wallet: that wallet's panel design. The contract never reads inside the word.

```solidity
contract PanelDesigns {
    mapping(address holder => bytes32) public designOf;
    event DesignSet(address indexed holder, bytes32 design);
    function setDesign(bytes32 design) external;                                   // sets msg.sender's word, emits DesignSet
    function clearDesign() external;                                               // zeroes msg.sender's word, emits DesignSet(holder, 0)
    function designsOf(address[] calldata holders) external view returns (bytes32[] memory); // in order, zero where unset
}
```

A wallet may set or clear only its own. No owner, admin, pause, fee, upgrade or access control of any kind.

## PanelRenderer

Returns a self-contained HTML page that draws any wallet's panel, from chain state alone.

`src/PanelRenderer.sol` must declare these two interfaces (the tests import them from it) and the contract:

```solidity
interface ISeats { function ownerOf(uint256 tokenId) external view returns (address); }
interface IPanelDesigns { function designOf(address holder) external view returns (bytes32); }

contract PanelRenderer {
    ISeats public immutable seats;
    IPanelDesigns public immutable designs;
    bytes32 public immutable scriptHash;
    uint256 public constant SEAT_COUNT = 2000;

    error EmptyChunk(uint256 index);
    error WrongScript(bytes32 got);

    constructor(ISeats seats_, IPanelDesigns designs_, address c0, address c1, address c2, address c3, bytes32 expectedHash);

    function chunks() external view returns (address[] memory);    // [c0, c1, c2, c3]
    function script() external view returns (bytes memory);        // the code: each chunk's bytecode after its first byte, in order
    function owners() external view returns (bytes memory);        // 2000 * 20 bytes: seat i's holder at [20i, 20i+20)
    function panelOf(address wallet) external view returns (string memory);
}
```

`owners()` asks `seats.ownerOf(i)` for each seat. A seat is zero when that call reverts, returns under 32 bytes, or returns
a word with any of its upper 96 bits set (not an address); a `seats` address with no code gives all zeros, not a revert.
A return of 32 bytes or more whose first word is a clean address is that address.

Constructor: store the arguments, `scriptHash = expectedHash`, and read nothing. A launch rehearses its deploy on an
empty chain, where the chunks have no code, so the constructor must not call, read or check any other contract.

Reading the script instead checks it, every time (`script()`, and `panelOf` through it):

1. Revert `EmptyChunk(i)` if chunk `i`'s code is shorter than 2 bytes, checking 0 to 3 in order.
2. Read the script from the four chunks (EXTCODECOPY from offset 1). If its keccak256 is not `scriptHash`, revert
   `WrongScript(actualHash)`. Wrong or missing art is never served.

`panelOf(wallet)` returns exactly this string, with no other bytes:

```
<!doctype html><html><head><meta charset="utf-8"><meta name="viewport" content="width=device-width,initial-scale=1"><title>IMD panel {W}</title></head><body><script>(async()=>{const z=Uint8Array.from(atob("{S}"),c=>c.charCodeAt(0));const t=await new Response(new Blob([z]).stream().pipeThrough(new DecompressionStream("gzip"))).text();(0,eval)(t);IMD.panel("{O}","{W}","{D}",{C})})()</script></body></html>
```

- `{W}`: the wallet, `0x` and 40 lowercase hex digits.
- `{S}`: base64 (standard alphabet, `=` padding) of `script()`.
- `{O}`: base64 of `owners()`.
- `{D}`: `designs.designOf(wallet)`, `0x` and 64 lowercase hex digits.
- `{C}`: `block.chainid` in decimal.

No owner, admin, setter, fee or upgrade. Nothing in either contract may change after deploy.

The art also listens for `postMessage` events; see its source.

## Limits

- `panelOf` must cost under 30,000,000 gas, so a public node will serve it as an `eth_call`.
- The launch is one transaction, capped at 2^24 gas; PanelDesigns and PanelRenderer must deploy in under 14,000,000 gas
  together (the tests measure this; about 1.5M is typical).
- Constructor arguments are static: addresses, `bytes32`.

## Launch

The launch is a job for the IMD swarm's contracts-only launcher: it deploys both contracts on Ethereum mainnet
(`chainId: 1`) in one transaction, batching them itself. First `PanelDesigns`, no arguments; then `PanelRenderer` with:

| argument | value |
| --- | --- |
| `seats_` | `0x0000eC93127BAA929E58E97dd0095A2BFb38ec1D` (identity.md) |
| `designs_` | `$contract:PanelDesigns`, the address the first deploy got |
| `c0` to `c3` | the four addresses above, in order |
| `expectedHash` | the hash above |

Do not deploy the `PanelCode` contracts again; they are already live.

## Acceptance

- `forge test` passes every test in `test/`, unchanged, along with any you add. `test/PanelShape.t.sol` reads the compiled
  artifacts and the deployed bytecode: each contract has exactly the listed functions and no others, and no fallback or
  receive; no SELFDESTRUCT, DELEGATECALL, CALLCODE, CALL, CREATE, CREATE2 or TSTORE; the renderer keeps no storage, has
  no SSTORE, and reads nothing of the block, caller or transaction (TIMESTAMP, NUMBER, PREVRANDAO, BLOCKHASH, COINBASE,
  ORIGIN, CALLER, GASPRICE, BASEFEE, BLOBHASH); PanelDesigns keeps only `designOf`. An owner, setter, upgrade path or
  extra function of any name fails it.
- No owner or admin role of any kind, so nothing in either contract takes the paying wallet (`$owner`) as an argument.
- Slither reports no `encode-packed-collision` or `incorrect-shift`.
- `src/code/`, `art/`, `test/` and `foundry.toml` are untouched; `tools/gen-code.py` regenerates `src/code/` byte for byte.
- After the launch, `scriptHash()` on the deployed renderer returns the hash above, and `chunks()` returns the four
  addresses above.
